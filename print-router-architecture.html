What this service does

The Print Router Service is a Spring Boot microservice that receives print requests from warehouse applications and routes them to the correct physical printer. It does this in two steps:

  • Printer Discovery — Queries Active Directory via LDAP to find all printers registered at a given warehouse location (e.g., 01680/LA/WHS/MGROFC).
  • IPP Print Submission — Constructs a binary IPP 1.1 Print-Job request and sends it over HTTP with Basic Auth to the Windows print server for the discovered printer.

Key behavior

  • 1First-match routing: The controller iterates over all discovered printers and returns 200 OK on the first successful IPP response. It does not try all printers.
  • 2Fail-through: If a printer responds with a non-200 status, the loop continues to the next printer in the list.
  • 3Final fallback: If no printer succeeds (or the list is empty), a 400 Bad Request is returned.

LDAP connection details

  • Protocol: Configured via jndi.ldap.protocol (e.g., ldaps://)
  • Auth: Simple bind with domain credentials
  • Timeout: 5 second connection timeout
  • Referrals: Ignored (avoids cross-domain chasing)
  • Paging: Uses PagedResultsControl with 1000-entry pages to handle large directories

Location-based filtering

The location parameter is used as a substring match against the AD location attribute. Special LDAP characters (\ * ( ) \0) are escaped to prevent injection. If no location is provided, all printQueue objects in the domain are returned.

IPP Response Parsing

The service reads the first 8 bytes of the IPP response:

  • Bytes 0-1: IPP version (major.minor)
  • Bytes 2-3: Status code (success if ≤ 0x00FF)
  • Bytes 4-7: Request ID (must match the sent itemNo)

Success status codes: 0x0000 (ok), 0x0001 (ok-ignored-attrs), 0x0002 (ok-conflicting-attrs)

Error Handling

  • 401 Unauthorized: Auth failure, reports WWW-Authenticate scheme
  • 403 Forbidden: User not authorized for this queue
  • 404 Not Found: IPP queue URL doesn't exist
  • IOException: Network / connectivity failure (502 Bad Gateway)
  • InterruptedException: Thread interrupted (500)
  • ID Mismatch: Response request ID doesn't match sent ID

Data flow summary

  • The locationId from PrintMetadata drives the LDAP query to find printers at that warehouse location.
  • The itemNo is used as the IPP request ID and for request-response correlation.
  • The printerName from each discovered PrinterMetadata is appended to the base IPP queue URL to target that specific printer.
  • The documentName becomes the IPP job-name suffix.
  • Six print-data types (ShippingLabel, Manifest, RtLabel, BOL, HandlingInstruct, ShippingDoc) are modeled but not yet used by the routing logic — only the metadata fields drive the current flow.
